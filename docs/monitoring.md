# Monitoring and Logging

## Two monitoring scopes

Lovelace participates in two observability environments:

1. An in-cluster kube-prometheus-stack managed by this repository.
2. A central monitoring stack on the Docker LXC, managed outside this repository.

Keeping this distinction explicit prevents an external scrape or dashboard change from being mistaken for a missing GitOps resource.

## In-cluster stack

Flux installs kube-prometheus-stack with a HelmRelease in the `monitoring` namespace. It provides Prometheus Operator resources, Prometheus, Alertmanager, Grafana, and standard Kubernetes dashboards.

Grafana is available through Traefik at:

```text
lovelace-grafana.caliconet.lab
```

Its administrator credentials are supplied by the SOPS-encrypted `grafana-admin` Secret. Grafana currently uses `emptyDir` storage intentionally. Provisioned dashboards return after restart, but dashboards created manually in the UI are ephemeral.

## Minecraft metrics

The Minecraft Service exposes:

| Port name | Port | Source |
| --- | ---: | --- |
| `minecraft` | 25565 | Minecraft server |
| `metrics` | 9940 | Paper Prometheus plugin |
| `network-metrics` | 9100 | node-exporter sidecar |

The `monitoring/configs/staging/minecraft` ServiceMonitor selects the Minecraft Service and scrapes both metrics endpoints.

The network exporter also reads Prometheus textfiles generated by the storage collector. These include:

- Filesystem size, used space, and available space
- Total `/data` size and file count
- Per-directory size and file count
- Region-file size and count by dimension
- Storage-scan success, duration, and timestamp

## Central Prometheus and Alertmanager

The Docker-LXC Prometheus also scrapes the x86 worker and Minecraft exporters. That configuration is not stored in this repository.

Current integration points:

| Job | Target | Friendly instance label |
| --- | --- | --- |
| Node exporter | `192.168.3.112:9100` | `k8s-worker-01` |
| Minecraft Paper | `192.168.3.112:9940` | `k8s-worker-01` |
| Minecraft network/storage | `192.168.3.112:9101` | `k8s-worker-01` |

The staging StatefulSet publishes the Paper and network exporters with host ports for these external scrapes. Central Alertmanager uses the friendly `instance` label in notifications.

Validate the external endpoints from the Docker LXC:

```bash
curl -fsS --max-time 5 http://192.168.3.112:9940/metrics | head
curl -fsS --max-time 5 http://192.168.3.112:9101/metrics | head
```

A `curl: (23)` after piping to `head` only means `head` closed the pipe after receiving enough lines; it does not indicate a failed scrape.

## Logging

Grafana Alloy runs in the `minecraft` namespace with namespace-scoped RBAC. It discovers the Minecraft pod, keeps only the `minecraft` container logs, attaches stable labels, and sends them to Loki on the Docker LXC.

Current Loki destination:

```text
http://192.168.3.120:3100/loki/api/v1/push
```

Inspect Alloy:

```bash
kubectl get pods -n minecraft -l app=alloy-minecraft-logs
kubectl logs -n minecraft deployment/alloy-minecraft-logs --tail=200
```

## Troubleshooting stale targets

If Prometheus continues scraping an old address after editing a bind-mounted configuration file, compare the host file with the file visible inside the container. Some in-place editors replace the host inode while the running container remains attached to the previous inode.

Validate the configuration and restart the container when necessary:

```bash
docker exec prometheus promtool check config /etc/prometheus/prometheus.yml
docker restart prometheus
```

Then query `up` again and verify the active configuration through the Prometheus API.
